This post will run through the labs on web sec academy by Portswigger related to XSS. 

### <u>Lab: Reflected XSS into HTML context with nothing encoded
Reflected cross-site scripting (or XSS) arises when an application receives data in an HTTP request and includes that data within the immediate response in an unsafe way.

In this lab the search feature is vulenrable to XSS and we can exploit this by entering `<script>alert(1)</script>` into the search.

### <u>Lab: Stored XSS into HTML context with nothing encoded
Stored cross-site scripting (also known as second-order or persistent XSS) arises when an application receives data from an untrusted source and includes that data within its later HTTP responses in an unsafe way.

In this lab we can have the XSS stored by commenting `<script>alert(1)</script>` in the post.

### <u>Lab: DOM XSS in document.write sink using source location.search
DOM-based XSS vulnerabilities usually arise when JavaScript takes data from an attacker-controllable source, such as the URL, and passes it to a sink that supports dynamic code execution, such as eval() or innerHTML. This enables attackers to execute malicious JavaScript, which typically allows them to hijack other users' accounts. 

We can input test in the search bar and see where it shows up in the code. We can see using document.write it shows up in:
```
<img src="/resources/images/tracker.gif?searchTerms=test" n8a00i5a9="">
```
Now we can exit out of that using "> to close the img tag and then we can put our own tags in the html like script to call alert using this payload:
```
"><script>alert(1)</script>
```

### <u>Lab: DOM XSS in innerHTML sink using source location.search
The innerHTML sink doesn't accept script elements on any modern browser, nor will svg onload events fire. This means you will need to use alternative elements like img or iframe. Event handlers such as onload and onerror can be used in conjunction with these elements.

After inputting test we see it shows up in:
```
<span id="searchMessage">test</span>
```
Since .innerHTML is used we can't use script but instead we can use an img tag with an error and call alert with onerror as such:
```
<img src=1 onerror=alert(1)>
```

### <u>Lab: DOM XSS in jQuery anchor href attribute sink using location.search source
If a JavaScript library such as jQuery is being used, look out for sinks that can alter DOM elements on the page. In this lab in the submit feedback form in the url there is a returnPath parameter where jQuery takes that and sets that as the href attribute for the back link. By changing the parameter to `javascript:alert(document.cookie)` we can cause an alert to display the cookies when the back link is clicked.
