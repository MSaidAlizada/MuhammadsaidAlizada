### Level 0:
The first level is simple all we need to is ssh into the level. It tells us to ssh into bandit.labs.overthewire.org on port 2220 with the username bandit0. Reading the man page we can the two flags we will need are -p and -l with -p for specifying the port and the -l for specifying the username. So our command is  
```
ssh bandit.labs.overthewire.org -p2220 -l bandit0  
```
and we enter the password bandit0. Once logging in using the ls command we see there is a readme file and with cat readme we can see the output:  
Congratulations on your first steps into the bandit game!!
Please make sure you have read the rules at https://overthewire.org/rules/
If you are following a course, workshop, walkthrough or other educational activity,
please inform the instructor about the rules as well and encourage them to
contribute to the OverTheWire community so we can keep these games free!

The password you are looking for is: ZjLjTmM6FvvyRnrb2rfNWOZOTa6ip5If

### Level 1:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit1  
```
In this level we are told the flag is stored in a file called ```-``` , however ```cat -``` will not work as this symbol instructs cat command to read from standard input. However if we put a ./ infront of it and execute ```cat ./-``` then this specifies that the symbol is a file name and we get the output 263JGJPfgU6LtdEvgfWU1XP5yac29mFx.

### Level 5:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit5
```
We are told the flag is in the file with the size 1033 bytes, human readable and not executable. For this we will use find command which can find a file in a directory given parameters. We will use the -size flag and -executable flag.
```
cd inhere
find ./ -size 1033c -not executable
```
This outputs:
```
./maybehere07/.file2
```
So outputting the file we get the flag HWasnPhtq9AVKe0dmk45nxy20cvUa6EG.

### Level 6:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit6
```
This time the file is stored somewhere on the server so we cd to the root directory. The file storing the the flag has the following restrictions: owned by user bandit7, owned by group bandit6 and 33 bytes. So again we will use the find command and the size flag but will also use to other flags, -user and -group. -user is used to specify who owns the file and -group to specify the group of the file. When we use the command we will get a list of files some of which give error permission denied but only one file doesn't give that error which is where the flag is stored. Since we don't want to manually search for the file within all the permission denieds we can use 2>/dev/null which discards all the errors.
```
cd ../../
find / -type f -user bandit7 -group bandit6 -size 33c 2>/dev/null
```
This will leave only one file output /var/lib/dpkg/info/bandit7.password which has the flag morbNTDkSW6jIlUc0ymOdMaLnOlFVAaj.

### Level 8:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit8
```
Again flag is stored in the file data.txt but is the only line that occurs once. Since there is no pattern we can't use grep but we can use a command uniq which can remove duplicate lines that occur consecutively. However since they must be consecutive we have to sort the file as well which we can do with the sort command.
```
sort data.txt | uniq -u
```
Which outputs 4CKMh1JI91bUIZZPXDqGanal4xvAg0JM.

### Level 11:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit11
```
This time data.txt has been encoded with rot13 where all the letters have been rotated by 13. That means a is now n in the file. We can use the tr command to translate the letters by giving it two sets. Our first set is the rotated set of letter which is 'N-ZA-Mn-za-m' and our second being the regular alphabet 'A-Za-z'.
```
bandit11@bandit:~$ cat data.txt | tr 'N-ZA-Mn-za-m' 'A-Za-z'
The password is 7x16WNeHIi5YkIhWsfFIqoognUTyj9Q4
```

### Level 12:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit12
```
We are told the file data.txt is a hexdump of a file that has been compressed repeatedly so if we want to get that flag we will have to reverse all of that. We are suggested to copy the data.txt to a temporary directory so that we can do all these changes.
```
bandit12@bandit:~$ mktemp -d
/tmp/tmp.oOkZZAosQF
bandit12@bandit:~$ cp data.txt /tmp/tmp.oOkZZAosQF
bandit12@bandit:~$ cd /tmp/tmp.oOkZZAosQF
```
Now we can begin with reversing starting with the hexdump we can xxd command to reverse with the -r flag and storing the output in file called flag.txt.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ xxd -r data.txt > flag.txt
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file flag.txt 
flag.txt: gzip compressed data, was "data2.bin", last modified: Thu Sep 19 07:08:15 2024, max compression, from Unix, original size modulo 2^32 574
```
As we can see checking the file type of flag.txt we can see it has been compressed by gzip which we can expand using gunzip but we need the file name to end with .gz.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv flag.txt flag.txt.gz
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ gunzip flag.txt.gz 
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file flag.txt 
flag.txt: bzip2 compressed data, block size = 900k
```
The file is still compressed but this time by bzip2 so we will use bunzip2 to expand but we have the rename the file to end with .bz2.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv flag.txt flag.txt.bz2
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ bunzip2 flag.txt.bz2 
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file flag.txt 
flag.txt: gzip compressed data, was "data4.bin", last modified: Thu Sep 19 07:08:15 2024, max compression, from Unix, original size modulo 2^32 20480
```
Again it is still compressed with gzip so we repeat.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv flag.txt flag.txt.gz
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ gunzip flag.txt.gz 
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file flag.txt 
flag.txt: POSIX tar archive (GNU)
```
This time it expanded to a tar archive which we can decompress with tar -xvf as it says on the man page.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv flag.txt flag.txt.tar
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ tar -xvf flag.txt.tar 
data5.bin
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file data5.bin 
data5.bin: POSIX tar archive (GNU)
```
Expanding it we see it returns a file called data5.bin which again is a tar archive so we repeat.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv data5.bin data5.bin.tar
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ tar -xvf data5.bin.tar 
data6.bin
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file data6.bin 
data6.bin: bzip2 compressed data, block size = 900k
```
This time we get data6.bin which compressed with bzip so ... repeat :0.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv data6.bin data6.bin.bz2
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ bunzip2 data6.bin.bz2 
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file data6.bin 
data6.bin: POSIX tar archive (GNU)
```
Expanding it we see it is tar type so again repeat :(.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv data6.bin data6.bin.tar
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ tar -xvf data6.bin.tar 
data8.bin
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file data8.bin
data8.bin: gzip compressed data, was "data9.bin", last modified: Thu Sep 19 07:08:15 2024, max compression, from Unix, original size modulo 2^32 49
```
Again it is gzip so expand again.
```
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ mv data8.bin data8.bin.gz
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ gunzip data8.bin.gz 
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ file data8.bin 
data8.bin: ASCII text
bandit12@bandit:/tmp/tmp.oOkZZAosQF$ cat data8.bin
The password is FO5dwFsc0cbaIiH0h8J2eUks2vdTDwAn
```
This time when we decompress it we get ASCII text file which is the the flag!!!.

MU4VWeTyJk8ROof1qqmcBPaLh7lDCPvS

### Level 14:
```
ssh bandit.labs.overthewire.org -p2220 -l bandit14
```
For this level we are told we get the password by submitting the current password to the port 30000 on localhost. This is a use case for nc (net cat) which allows us to send and recieve packets.
```
bandit14@bandit:~$ nc localhost 30000 < /etc/bandit_pass/bandit14
Correct!
8xCjnmgoKbGLhHFAZlGE5Tmu4M2tKJQo
```
With the command above we send the file /etc/bandit_pass/bandit14 which is where the password is stored.
