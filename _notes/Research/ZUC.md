## Introduction

- ZUC => Stream cipher used to encrypt communications in mobile networks

- Stream cipher
    - Initial seed is provided which generates a stream of data that is pseudoranom
    - Stream is mixed with plain text for encryption
    - Receiver will have same secret key (seed), thus can generate the same keystream

- Symmetric key cryptosystem
    - If key K is used for encrypting a message then the same key K has to be used for decryption
    - Divided into 2 categories:  
        1) Block cipher : Message is divided into multiple fixed length blocks which are then individualy encrypted with secret key, then decryption is also done block wise.  
        2) Stream cipher : Encryption/Decryption is done characterwise, pseudorandom sequence generated with equal length to the message, it is then bitwise XORed withe the message and the result is transmitted
    - One time Pad : A long sequence of pseudorandom bits where a portion of it can be used each time for encryption/decryption, but needs to be shared with reciever in advance
        - The distribution of One Time Pads is the issue though
    - Thus there is a need for a pseudorandom bit generator that also given the initial sequence of generated bits it should not be possible to efficiently guess the next bit with chances of success significantly greater than half

## Prerequisites
- Finite Fields
    - A field is a nonempty set that has 2 operations, + and ·
    - It must also satisfy the follwing:
        - (F,+) is commutative
        - If 0 denotes is the identify element in (F,+) then (F\\{0},·) is commutative
        - For all a,b,c ∈ F, a · (b + c) = a · b + a · c
    - If a field has finite elements then it is a Finite Field
    - If the complete multiplicative group (F\\{0},·) can be generated by an element of F\\{0} then (F\\{0},·) is known as a cyclic group and the element is called a primative element of F\\{0}
    - Prime fields, also called Galois Field, are fields that are the remainders of a prime p
    - Two Properties hold for fields:
        - Two finite fields with the same number of elements are isomorphic
        - Every finite field has exactly pⁿ elements for some prime number p and positive integer n
- Field Extension
    - If F₂ ⊆ F₁, F₂ is closed under both operations, and F₂ is itself a field, then F₂ is a subfield of F₁, and F₁ is a field extension of F₂
- Polynomials over a field
    - To build extensions we need to use polynomials
    - A polynomial over GF(p):
        - f(x) = c<sub>0</sub> + c<sub>1</sub>x + c<sub>2</sub>x<sup>2</sup>+...+c<sub>m</sub>x<sup>m</sup>  where c<sub>i</sub> ∈ GF(p) and c<sub>m</sub> != 0
        - Degree of f is m (highest power with a nonzero coefficient)
    - F[x] denotes the set of all polynomials with coefficients from F, but F[x] is a ring not a field
    - Irreducible poylnomial : Polynomial p(x) with degree ≥ 1 ∈ F[x] is irreducible if it can't be written as p<sub>1</sub>(x) · p<sub>2</sub>(x) where both degree ≥ 1
        - I = ⟨p(x)⟩ = {p(x)·q(x) : q(x) ∈ F[x]}
        - F[x]/⟨p(x)⟩ is a field
    - Let p(x) be irreducible with formal root α. If α is a primitive element of the extension field (its powers generate all of F*), then p(x) is called a primitive polynomial.
        - Every primitive polynomial is irreducible, but not every irreducible polynomial is primitive.

## Design Specification of ZUC Stream Cipher
- ZUC has two phases:
    - Key-IV initialization phase
        - State of the cipher will be initialized by n 128-bit secret key and a 128-bit initialization vector
        - Also the Key Scheduling Algorithm will run for 32 rounds without generating an output
    - Key Generation phase
        - Cipher outputs 32 bits in every round
- ZUC designed based on three major components:
    - One Linear Feedback Shift Register
    - One Bit Reorganization Layer
    - One nonlinear function
- LFSR
    - Usually most stream ciphers are built on extensions of GF(2) which means the LFSR will bits, but ZUC insteads is built on GF(2<sup>31</sup>-1) so the LFSR holds integers
        - GF(2<sup>31</sup>-1) is a prime field since 2<sup>31</sup>-1 is a prime
        - The elements of the field are {1,2,...,2<sup>31</sup>-1} with 0 being represented as 2<sup>31</sup>-1
    - The LFSR is a 16 word register which each state being 31 bits
        - In most stream ciphers the LFSR states would be 1 bit each
    - ZUC uses a primitive polynomial since that guarantees maximum period. One such polynomial is:
        - f(x) = x¹⁶ − (2¹⁵x¹⁵ + 2¹⁷x¹³ + 2²¹x¹⁰ + 2²⁰x⁴ + (2⁸+1))
        - So its feedback function would be:  
            - s₁₅<sup>t+1</sup> = 2¹⁵s₁₅ + 2¹⁷s₁₃ + 2²¹s₁₀ + 2²⁰s₄ + (2⁸+1)s₀ (mod 2³¹−1)  
        - Thus the state update function would be:  
            - s<sub>i</sub><sup>t+1</sup> = s<sub>i+1</sub><sup>t</sup> for i <= 14  
            - s<sub>15</sub> = 2¹⁵s₁₅ + 2¹⁷s₁₃ + 2²¹s₁₀ + 2²⁰s₄ + (2⁸+1)s₀ (mod 2³¹−1) 
    - The addition is done using a 31 bit adder and the multiplication is done through shifting
    - In most cases shifting would cause overflow issues however having mod 2<sup>31</sup>-1 fixes this issue:
        - Multiplying by 2<sup>k</sup> would just be a shift of k however if we are shifting position i (its current weight would be 2<sup>i</sup>) then its new position would be i+k
        - But if i+k is an overflow position then it can also be written as i+k=31+j, and the weight would be 2<sup>31+j</sup> which can be split 2<sup>31+j</sup>=2<sup>31</sup>·2<sup>j</sup>
        - But since 2<sup>31</sup> is equal to 1 in mod 2<sup>31</sup>-1 thus 2<sup>31+j</sup>=2<sup>31</sup>·2<sup>j</sup> = 1·2<sup>j</sup>
        - So that means the bits new position will be j which isn't causing an overflow
    - The LFSR runs in two modes:
        - First key initialization in which the output from the nonlinear function is fed back into the LFSR and added onto the feedback (XORed in ZUC 1.4)
            - This is done so that similar keys don't produce similar keystreams
        - Once the previous mode is done it switches to key generation where the nonlinear function is the output and not fed into the LFSR anymore
- Bit Reorganization Layer
    - Bit Reorganization Layer consists of 4 32 bits registers, X<sub>0</sub>,X<sub>1</sub>,X<sub>2</sub>,X<sub>3</sub>
    - They are formed through concatentating states of the LFSR
        - X<sub>0</sub> = S<sub>15H</sub>||S<sub>14L</sub>
        - X<sub>1</sub> = S<sub>11L</sub>||S<sub>9H</sub>
        - X<sub>2</sub> = S<sub>7L</sub>||S<sub>5H</sub>
        - X<sub>3</sub> = S<sub>2L</sub>||S<sub>0H</sub>
- Nonlinear Function
    - Consists of 3 main componenets:
        - 2 32-bit registers, R<sub>1</sub> and R<sub>2</sub>
        - 2 linear transformation functions, L<sub>1</sub> and L<sub>2</sub>
        - 2 S-boxes, S<sub>1</sub> and S<sub>2</sub> : {0,1}<sup>8</sup> -> {0,1}<sup>8</sup>
    - L1(X) = X ⊕ (X ⋘ 2) ⊕ (X ⋘ 10) ⊕ (X ⋘ 18) ⊕ (X ⋘ 24)
    - L2(X) = X ⊕ (X ⋘ 8) ⊕ (X ⋘ 14) ⊕ (X ⋘ 22) ⊕ (X ⋘ 30)
    - S-boxes create the nonlinear element and make up the S function:
        - S(x) = S0(x ≫ 24) ‖ S1((x ≫ 16) & 0xFF) ‖ S0((x ≫ 8) & 0xFF) ‖ S1(x & 0xFF)
    - Algorithm:
        ```
        X0 ──⊕── R1
            └──⊞── R2 ──→ W  (→ ⊕ X3 → keystream)

        X1 ──⊞── R1 ──→ W1 ─┐
                            ├─ split into halves, cross over
        X2 ──⊕── R2 ──→ W2 ─┘
                                ↓
                W1_L‖W2_H → L1 → S → R1 (next)
                W2_L‖W1_H → L2 → S → R2 (next)
        ```
